# Traps, ranked, with the evidence that found them

All measured on 2026-10-19 on a stock xmcloud-starter-js environment unless noted.

0. **The Create Site dialog runs the scaffold in a different context than `createSite` over Authoring GraphQL.** A site created in the dialog from a template that passed **template paths** to `New-Item -ItemType` aborted on the first datasource. The Spe.log entry: `NewItem(... itemTypeName='/sitecore/templates/…/Promo') NullReferenceException at PsSitecoreItemProvider.ForceItemLanguage`. Pages (created by template **ID**) survived, and every layout stayed empty. The same template was VERIFIED through the API, so an API smoke test is not proof for the dialog path.
   *Rule:* generated scripts reference templates by ID and pin every path to `master:`. When a dialog-created site looks empty, read `Spe.log` through the Deploy monitoring API (`/api/logs/v2/<env>/<file>`).
1. **Collection contamination.** The starter's `Site N Site Setup` scripts set `"$templatesRoot/Page"."__Base template"` to their own page template, and create `Article Page`, `Landing Page`, … in the collection. After a SYNC site, a template whose pages sit on `Base Page` gets **`Article Page`** in that collection: `Set-TenantTemplate` takes the first derived template. Its `Title` write was then a silent no-op. In a fresh collection the same template yields `Page`.
   *Rule:* never mutate shared collection templates. Create uniquely named collection types that inherit module type + collection `Page`. Smoke-test in a fresh collection, and expect the generator's guard to throw when another family owns a type name.
2. **Scaffold exceptions do not fail the job.** A throwing ExecuteScript leaves the job `FINISHED` with a half-built site (Home 0/1 components). `job.status.exceptions` carries the message. Mutation-tested: `verify-template --smoke` reports FAILED.
3. **The rendering host is not validated.** SYNC's PostSetupStep wrote `kit-nextjs-product-starter` on an environment without that host, so `solutionSites.renderingHost` was null and nothing raised an error. The generator warns in the lint and in the job log; verify asserts the host resolves.
4. **Sites depend on template modules after creation.** Renderings are referenced (`Available Renderings/<module>`), not copied. Collection page types inherit module types. On a Sitecore-provisioned demo CM, a later platform deploy removed the starter templates' items: the master index still listed them (ghosts), the dialog lost them, and the existing site kept its content but had an empty layout. So keep template modules in every deploy, and resolve index hits as items (a search count proves nothing).
5. **Site names are CM-wide unique** (`SiteManagement:400 A site with that name already exists` across collections).
6. **Index ≠ discovery.** On a fresh CM, a `_template` search for Solution templates returns 0 while the dialog lists 5. The dialog uses `solutionTemplates`.
7. **Field inheritance.** `Title` and `Content` are own fields of each collection's `Page`, not of `Base Page` or any shared base. A page type that inherits only the shared bases has no Title.
8. **Silent field writes.** `$item["Missing"] = 'x'` does nothing. The generated `Set-Fields` throws, and the lint checks names first.
9. **Enabled=0 is shown greyed out,** not hidden. A missing thumbnail gives a grey skeleton card. Both were confirmed in the UI.
10. **Edge preview lag + Git Bash path rewriting.** Layout is null for a few seconds after creation. `node x.mjs /` in Git Bash receives `C:/Program Files/Git/`. Set `MSYS_NO_PATHCONV=1`.
11. **`itemTemplate(where:{path})` fails** for `/sitecore/templates/Feature/...` datasource templates. Resolve the path to an id, then query by `templateId`.
12. **The org deploy-admin token is enough for Authoring GraphQL writes,** but the xmapps Sites API (`/api/v1/sites/templates`) answers 401 to it. Everything here uses Authoring GraphQL, so no environment-scoped client is needed.
13. **Starter code smells not to copy:** stale `authoring/spe-scripts/site-*-setup.ps1` vs the serialized scripts; `AddItem` Names that do not match the branch root (`Pages` for a Video branch); a hard-coded host per template; a `$productPageDesign` undefined in two scripts.
14. **Home ignores page-type insert options.** The `JSS Site` skeleton gives Home an item-level `__Masters` = `Base Page`, so every page type and blueprint set on standard values is invisible under Home. Measured on sites from two generated templates and from Basic. The generator now sets Home at item level, `build-blueprint` detects the override, and verify asserts it.
15. **Basic writes `s:par` with a leading `?`** (`?Styles=…`). A naive parser sees the key `?Styles`.
16. **Basic's script creates site-local items that layouts reference by id:** the `Banner` variant of Image, and Styles under `Presentation/Styles/BasicSite`. A captured layout needs them in the new site. Hence `site:` tokens, plus variants created on demand. Without that, the first missing variant threw and aborted every later component (the job still said FINISHED).
17. **A component failure must not abort the scaffold.** Components are added inside try/catch, and failures are collected and thrown once at the end. Mutation-tested: 2 of 3 components survive, the job names the failed one, verify exits 1.
18. **`removeSiteCollection` cascades:** it deletes the collection's templates, branches, settings, media and content folders. Module page types can stay locked for a few seconds while that runs; `remove-template` reports such a path instead of stopping.
19. **A page blueprint's datasources must be `local:`.** Absolute ids inside a branch would keep pointing at the branch's own items. With `local:/Data/x`, `$name` expands in Title and datasource fields alike, measured on a page created via `createItem(templateId = branch id)`, which is what Pages does.
20. **Smoke cleanup removed a reused collection (2026-10-21).** `verify-template --smoke --collection <existing>` without `--keep` ran `removeSiteCollection` on a collection it had not created, and trap 18 makes that cascade. Now the collection is removed only when the run created it, and `--collection` without `--keep` is refused (exit 2). Never point `--collection` at a shared collection. The same applied to sites: `--site-name` named an existing site, createSite reported the conflict only inside the job, and cleanup then removed that site (reproduced on a stub, not a CM). A site name that already exists is now refused before anything is created, and `--site-name` requires `--keep`.
21. **A variant on a custom rendering failed the component (2026-10-24).** Only the OOTB renderings ship a `Headless Variants/<rendering>` folder, so every custom rendering hit `no Headless Variants folder` and the component was dropped. `Ensure-Variant` now creates the folder (sibling folder's template) and the definition (an existing definition's template). If the site has no variants content at all it throws a named error.
22. **Spec keys the generator did not know were dropped silently.** `dictionary[]` and `settings{}` are now supported, and any other unknown top-level key warns. An empty `RobotsContent` serves `Disallow: /`, so set it in `settings`.
23. **A datasource is not one item (2026-10-24).** List components keep their rows as children of the datasource, and Pages offers "insert" on the datasource item only when its `__Masters` names the row template. A generated site without them renders the heading over an empty grid, and nothing errors. Use `datasource.children` and `datasource.insertOptions`; verify reads both back. A per-site reference field on the datasource (a model pick, say) is still set by hand.
24. **A placeholder reached a double-quoted PowerShell string (found in review, 2026-11-04; reproduced on the emitted script, not on a CM).** A nested container's placeholder is built as `"<placeholder>/container-$dynN"`, so `headless-main$(Write-Output PWNED)` from a spec or a captured layout became a real subexpression. It is now escaped there, and a placeholder outside `^/?[A-Za-z0-9_{}/-]+$` is a spec error.
25. **A blueprint is layout XML, not a scaffold script.** It has no `Ensure-Variant` and no `Resolve-SiteRefs` step, so `variant` and `site:` tokens used to vanish or land raw. Both are now spec errors inside a blueprint, and `extract-spec --page` warns when a captured page needs them.
