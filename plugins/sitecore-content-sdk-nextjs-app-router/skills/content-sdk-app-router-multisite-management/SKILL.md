# Content SDK Multisite Management (App Router)

Site resolution from the request (hostname or cookie); `AppRouterMultisiteProxy` rewrites to `/[site]/[locale]/...path`. **LocaleProxy runs before multisite** so next-intl and the site resolver see the correct locale.

## When to use

- User asks about multiple sites, hostnames, or site resolution.
- Task involves `.sitecore/sites.json`, multisite config, or the proxy (`src/proxy.ts`).
- User mentions "multisite," "site resolution," "hostname," "sites.json," or "proxy chain."

## The proxy chain (template 2.4.0)

Source of truth: `create-content-sdk-app@2.4.0` → `dist/templates/nextjs-app-router/src/proxy.ts` (lines 16-28, 105; the cache-components template's file is byte-identical).

```ts
export default function proxy(req: NextRequest, event: NextFetchEvent) {
  const preview = new PreviewProxy({ client, ...scConfig.api.edge });
  const botTracking = new BotTrackingProxy({ ...scConfig.api.edge, sites, fetchEvent: event });
  const locale = new LocaleProxy({ sites, locales: routing.locales.slice(), defaultLanguage: scConfig.defaultLanguage, skip: () => false });
  const multisite = new AppRouterMultisiteProxy({ sites, ...scConfig.multisite, skip: () => false });
  const redirects = new RedirectsProxy({ sites, ...scConfig.api.edge, ...scConfig.api.local, ...scConfig.redirects, skip: () => false });
  const personalize = new PersonalizeProxy({ sites, ...scConfig.api.edge, ...scConfig.personalize, skip: () => false });
  return defineProxy(preview, botTracking, locale, multisite, redirects, personalize).exec(req);
}
```

| # | Proxy | Why it sits here |
|---|---|---|
| 1 | `PreviewProxy` | Authorizes preview / editing requests on the editing host; no-op elsewhere |
| 2 | `BotTrackingProxy` | Detects bots (`isbot`), sets the `sc_bot` cookie and sends a `botPageView` via `fetchEvent.waitUntil`. **Must precede `PersonalizeProxy`**: `skipForBot` (default `true`) reads `sc_bot` to skip the personalize lookup for bots ("Lightweight Tracking") |
| 3 | `LocaleProxy` | Sets the locale before anything resolves a site |
| 4 | `AppRouterMultisiteProxy` | Resolves the site, rewrites to `/[site]/[locale]/[...path]` |
| 5 | `RedirectsProxy` | Applies authored redirects for the resolved site |
| 6 | `PersonalizeProxy` | Last: rewrites to the `_variantId_` path; owned by `content-sdk-personalization` |

- **Proxies are instantiated per request**, inside the exported function, because `BotTrackingProxy` needs that request's `NextFetchEvent`. Do not hoist them to module scope.
- **Doc disagreement:** Sitecore's Lightweight Tracking page says `BotTrackingProxy` "must be the first proxy", but the scaffold puts `PreviewProxy` first. Follow the scaffold: preview requests must be authorized before anything else, and the invariant that matters is bot tracking **before personalize**.
- **`xmcloud-starter-js` main lags the template:** 5 proxies, no `BotTrackingProxy`, module-scope instances, although its `package.json` is on 2.4.0. Do not copy its `proxy.ts` as the reference; the create-content-sdk-app template is.
- **`src/proxy.ts` alone is enough on Next 16.** `next build` lists `Proxy (Middleware)` with no `middleware.ts`. The template's own `.agents/docs/AGENTS-router-specifics.md` still says to add a `src/middleware.ts` re-export; that line is stale. Do not add one.

## Hard Rules

- Site list is in `.sitecore/sites.json` (generated by the Sitecore CLI or deployment). Avoid hand-editing unless the format is known.
- **Keep the template order:** preview → botTracking → locale → multisite → redirects → personalize. Insert custom proxies relative to it; never move locale after multisite or botTracking after personalize.
- **Languages across sites** (measured 2026-10-02): `LocaleProxy` ignores `site.language` (one global default). A site name containing `_` breaks the `${site}_${locale}` request key. A `sites.json` entry Edge does not know fails `next build` (`[IV-007]`). See `content-sdk-app-router-dictionary-and-i18n`.
- **Matcher:** exclude API routes, `_next/`, sitemap, robots, healthz, `sitecore/api/`, `-/` (media) and static assets so the proxy stays lightweight.
- Config: `sitecore.config.ts` → `multisite`, `redirects`, `personalize`. Single `SitecoreClient`; pass the resolved site and locale from route params into `getPage`, `getDictionary`, etc.
- Personalize options (`skip`, scope, timeouts, `enabled`): `content-sdk-personalization` and `content-sdk-site-setup-and-env`. Consent gating (`PersonalizeProxy.skip` on a consent cookie): `content-sdk-tracking-consent`.

## Stop Conditions

- Stop if the user wants to move locale after multisite or bot tracking after personalize; explain the dependency.
- Stop if `sites.json` format is unknown and the change could break resolution; suggest checking SDK docs or CLI output.
- Do not add a second site resolution mechanism; use the existing proxy and config.
